# Lock-in Amplifier on Zynq-7020 (Red Pitaya)

Open-loop digital lock-in amplifier at **200 kHz** for the **Red Pitaya STEMlab 125-14**
(Zynq-7020, `xc7z020clg400-1`, 14-bit ADC/DAC, 125 MHz sampling clock).

The FPGA generates the modulation signal on the DAC, demodulates the signal acquired by the ADC,
decimates it and streams the result to the PS DDR through AXI DMA.

The repository contains sources only: the Vivado project is regenerated from Tcl.

## Designs

Two block designs are provided.

### `open_loop_200KHz` – sine modulation, I/Q demodulation

```
DDS sine ──► DAC
ADC B ─► FIR 32 taps ─► splitter ─┬─► × DDS (0°)  ─┐
                                  └─► × DDS (90°) ─┴─► I/Q mux ─► CIC R=2048 ─► ↓2 ─► FIR 64 taps ─► ↓100 ─► TLAST ─► DMA
```

- Frequency set by `phase_step` (`xlconstant_0`): f = phase_step · 125 MHz / 2³².
  The block design uses **6800000 → 197.9 kHz**; exactly 200 kHz requires **6871948**.
- DAC sine phase and I/Q selection come from `axi_gpio_0` (`gpio_o`).
- Output rate to the DMA: 125 MHz / 2048 / 2 / 100 ≈ **305 Hz**.

### `open_loop_200KHz_square` – square-wave modulation

```
Square wave (312 + 312 cycles) ──► DAC
ADC B ─► demodulator (Σ half-period 1 − Σ half-period 2) ─► CIC R=8 ─► ↓2 ─► FIR 64 taps ─► ↓50 ─► TLAST ─► DMA
```

- Period of 624 cycles → 200.32 kHz.
- The demodulator integrates every sample of each half-period. Parameters:
  `PHASE_DELAY` (DAC → ADC loop delay, in samples) and `BLANK` (samples discarded after each edge).
- Output rate to the DMA: 200.32 kHz / 8 / 2 / 50 ≈ **250 Hz**.

In both designs a DMA frame is 68000 samples long (`TLAST`).

## Repository layout

```
rtl/      RTL modules (block design module references), one file per module
bd/       block designs exported with write_bd_tcl
constr/   Red Pitaya constraints (pins and clocks)
mem/      sine LUTs + gen_lut.py to regenerate them
sim/      testbench
docs/     filter response plots + script to regenerate them
build_project.tcl   creates the Vivado project in vivado/
export_bd.tcl       re-exports the block designs to bd/ after a change
```

## Requirements

- Vivado **2025.2** (Xilinx IPs are exported without version, so nearby releases should work)
- Python 3 with NumPy and Matplotlib (only to regenerate LUTs and plots)

## Building the project

From the Vivado Tcl console (no project open):

```tcl
cd <path to this repository>
source build_project.tcl
```

The project is created in `vivado/` (ignored by git) with `open_loop_200KHz_square_wrapper` as top.
To use the sine design, change `top_wrapper` at the top of `build_project.tcl`.

> On Windows Vivado cannot handle paths longer than 260 characters: clone the repository
> into a short path (e.g. `C:/fpga/...`).

## Editing workflow

1. Edit the RTL in `rtl/` and/or the block designs in the open project.
2. If a block design changed: `source export_bd.tcl` (rewrites `bd/*.tcl`).
3. Commit `rtl/`, `bd/`, etc. Never commit `vivado/`.

## Sine LUT

`mem/lut_sin.mem`: 2048 samples over one period, amplitude ±4000, 16-bit two's complement,
read by `Axis_dds_sine_2048` with `$readmemh`. The output frequency is set by `phase_step`, not by the LUT.
`mem/lut_sin_200k_625.mem`: exactly one 200 kHz period at 125 MHz (625 samples),
for a direct-readout generator.

```
python mem/gen_lut.py
```

## Simulation

`sim/tb_square.v` checks the chain square wave → channel (delay, gain, offset) →
demodulator → CIC against the expected value. It is the `sim_1` top in the project:
*Run Simulation → Run Behavioral Simulation*, then `run all`. It must print `errori: 0`.

## Known limitations

- The I/Q mux acquires I **or** Q: both cannot be acquired at the same time.
- The custom AXI-Stream blocks do not really handle backpressure (they work because the stream
  is continuous); samples are lost if the DMA is not ready.
- `Add_tlast_tkeep`: registered `tready` and 8-bit `tkeep` on a 32-bit bus.
- The FIR filters are windowed moving averages with about −20 dB first sidelobe:
  out-of-band noise folds back after the following decimation.
